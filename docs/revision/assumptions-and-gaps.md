# STRIDERA Revision — Assumptions, Decisions & Gaps

| Ref | Topic | Classification | Decision / Implementation Detail |
|---|---|---|---|
| **D1** | Order status vocabulary | **Conflicting** | Canonical statuses: `PENDING`, `PAID`, `SHIPPED`, `CANCELLED` (preserving `CONFIRMED`/`DELIVERED` compatibility for existing flows; Admin UI displays `PENDING` as `PENDING (Unpaid)`). |
| **D2** | Multi-seller order slicing & fulfillment | **Missing** | `OrderItem` has `fulfillmentStatus` (`PENDING`, `SHIPPED`, `CANCELLED`), `shippedAt`, and `stockConflict`. Parent `Order.orderStatus` derives: `PENDING` until paid; `PAID` once paid; `SHIPPED` when all non-cancelled items are shipped; `CANCELLED` when all items are cancelled; `"Partially shipped"` as derived UI label. Sellers only see/ship their own items on `PAID` orders. |
| **D3** | "Signed-in sellers" in Admin Analytics | **Inferred** | Interpreted as all `APPROVED` sellers, enriched with `lastSeenAt` (throttled to max once/minute) and an **"Online now"** badge when seen within the last 10 minutes. |
| **D4** | Persistent sessions | **Source-defined / Recommended** | `User.sessionTokenHash` stores SHA-256 hash of opaque session token (`crypto.randomBytes(32)`), sent via HttpOnly `SameSite=Lax` cookie (`stridera_session`) + JWT compatibility for existing API clients. Expires in 30 days ("Keep me signed in" default ON). Rotated on login, cleared on logout, invalidated on password change, suspension, or role change. *Limitation:* single `sessionTokenHash` per user means one active persistent session per user at a time (a `user_sessions` table is a Recommended future upgrade). |
| **D5** | Seller onboarding | **Inferred** | `sellerStatus` (`PENDING`, `APPROVED`, `REJECTED`, `SUSPENDED`) + `accountStatus` (`ACTIVE`, `DEACTIVATED`, `SUSPENDED`). `PENDING` sellers see a dedicated "Awaiting Approval" screen. `SUSPENDED` sellers' products are hidden from storefront/search while order history remains intact. |
| **D6** | Role & permission safeguards | **Recommended** | Admin cannot demote or suspend the last remaining `ADMIN` user, nor demote/suspend themselves (no self-lockout). All changes write to `audit_logs`. |
| **D7** | API keys, webhooks & health | **Inferred / Recommended** | `system_settings` stores API keys encrypted at rest with AES-256-GCM (`SETTINGS_ENCRYPTION_KEY`), displayed masked (last 4 chars), never returned in full, and rejects live-mode keys (`sk_live_`, `pk_live_`). `webhook_events` logs all incoming webhooks (including invalid signatures with 401). `/api/admin/health` reports real DB reachability, sandbox status, last webhook, 24h failures, and `DEMO_FALLBACK_ENABLED`. |
| **D8** | Metric definitions | **Missing / Inferred** | Only `PAID` / `SHIPPED` / `DELIVERED` order items count (`PENDING` and `CANCELLED` excluded). Periods: `7d`, `30d` (default), `90d`, `all` (UTC storage, `Asia/Manila` display). Within a seller's active products: High-selling = top 20% by units (min 1), Low-selling = bottom 20%, No sales = 0 units. Under 5 active products: ranked without High/Low badges. Money summed in integer centavos. |
| **D9** | Transactional stock decrement | **Inferred** | Stock is validated at checkout, then atomically decremented **only upon payment confirmation** inside `finalizePayment()` using conditional `UPDATE product_variants SET stock_quantity = stock_quantity - qty WHERE id = $1 AND stock_quantity >= $2`. Duplicate webhook/simulate calls are no-ops. If conditional update fails (concurrent purchase of last pair), `OrderItem.stockConflict = true` is flagged and shipping is blocked until resolved. |
| **D10** | Authorization model | **Source-defined** | Centralized `authenticate`, `requireRole(...)`, and `getOwnedProductOr404(productId, sellerId)`. `sellerId` always comes from `req.user.id`. Alien seller resources return `404` (not `403`). |
| **D11** | Soft archive state | **Inferred** | `Product.status` (`ACTIVE`, `DRAFT`, `ARCHIVED`) synced with `isActive`. Archived products are hidden from storefront, search, and add-to-cart, never deleted when referenced by orders. |
| **D12** | Product images | **Inferred** | Accepts PNG, JPG, WEBP up to 2 MB, validated by magic bytes (file header), stored with randomized UUID filenames in `backend/public/uploads/products/`, capped at 6 images per product. |
| **D13** | Simulate Payment Success | **Source-defined** | Gated behind `DEMO_FALLBACK_ENABLED=true` (or `DEMO_MODE=true`) + `sandboxMode`, callable by order owner or Admin, records provider `SIMULATED`, writes `audit_logs`, and is distinguishable in admin analytics (`simulatedRevenueCentavos` vs `gatewayRevenueCentavos`). |
| **D14** | Storefront seller visibility | **Recommended** | Product cards, PDP, cart, and checkout display `Sold by {storeName}` badge. |
| **BS-01** | Extra staff roles from prior draft | **Beyond-spec** | `INVENTORY_MANAGER`, `DELIVERY_PERSONNEL`, `CUSTOMER_SUPPORT`, `FINANCE_OFFICER` routes (`/api/inventory`, `/api/delivery`, `/api/support`, `/api/finance`) and UI pages (`/inventory`, `/delivery`, `/support`, `/finance`) remain functional and untouched. Owner should confirm whether to retain or retire them. |
| **BS-02** | Promo/Coupon engine | **Beyond-spec** | Existing `promotions` table and promo code input at checkout remain functional; not extended. |
